# 09 操作日志与审计

## 今天要建立的理解

操作日志是企业系统非常看重的能力。它回答的是：谁在什么时候对什么东西做了什么改动，改动前后是什么。对于订单、库存、工单这类业务，出问题时能不能追踪非常重要。

## 你要重点考虑的问题

先区分系统日志和审计日志。系统日志通常给开发者排查错误，比如异常堆栈和接口耗时。审计日志给业务和管理使用，记录关键业务动作。

再考虑哪些动作必须记录。登录可以记录，库存调整必须记录，订单状态变化必须记录，工单处理必须记录。普通查询不一定都要记录，否则日志会太多。

还要考虑日志内容。只记录“修改成功”价值不大。更好的日志应该有操作人、操作类型、对象类型、对象 ID、操作前状态、操作后状态、时间、IP、备注。

## 建议你查什么

推荐关键词：

- audit log table design
- business audit trail system
- operation log Spring Boot AOP
- audit log before after value
- system log vs audit log

你可以了解 AOP，但不一定一开始就用 AOP。先能手动记录关键业务日志也可以。

## 怎么问 AI 更有效

可以问：

“我想给订单库存系统加操作日志。请你帮我区分哪些动作需要审计日志，哪些只需要普通系统日志，并设计日志字段。”

也可以问：

“我现在不知道该手动写日志还是用 AOP。请根据初级 Java 项目的学习价值和复杂度帮我分析。”

## 你应该产出的东西

你需要完成：

- 操作日志表
- 关键业务动作写日志
- 日志查询接口
- 按用户、操作类型、时间筛选
- 普通用户不能删除日志

你还应该准备一个演示场景：修改库存后，打开日志页面看到谁改了什么。

## 复盘问题

- 审计日志和系统日志有什么区别？
- 为什么库存调整必须记录？
- 日志是否应该允许修改？
- 出现订单异常时，我能不能通过日志还原过程？
