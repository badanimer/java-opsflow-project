# 08 异常工单模块

## 今天要建立的理解

工单模块让你的项目从普通订单系统变成企业运营系统。真实公司里，系统不可能永远正常运行。订单失败、库存异常、支付状态不一致、用户投诉，都需要有人跟进。工单就是把异常变成可分配、可追踪、可关闭的任务。

## 你要重点考虑的问题

先考虑工单从哪里来。工单可以人工创建，也可以由系统自动创建。比如订单创建失败但库存状态可疑时，系统可以生成异常工单给 Operator。

再考虑工单状态。OPEN 表示待处理，IN_PROGRESS 表示处理中，RESOLVED 表示已解决，CLOSED 表示确认关闭。你要想：谁能把工单从 OPEN 改成 IN_PROGRESS？谁能关闭？是否允许 CLOSED 再打开？

还要考虑工单和订单的关系。不是所有工单都关联订单，但异常订单工单应该能追溯到具体订单。工单里应该有处理备注，方便别人理解处理过程。

## 建议你查什么

推荐关键词：

- ticket management workflow
- incident ticket status lifecycle
- order exception handling workflow
- helpdesk ticket priority severity
- backend operations ticket system

查的时候重点看状态流转和责任人，不要只看字段。

## 怎么问 AI 更有效

可以问：

“我想给订单系统加异常工单模块。请你从真实后台运营角度帮我设计工单类型、优先级、状态流转和权限控制。”

也可以问：

“哪些订单异常适合自动创建工单？哪些异常只需要返回错误给用户？请帮我区分。”

## 你应该产出的东西

你需要完成：

- 工单创建
- 工单分配
- 工单状态更新
- 工单备注
- 按状态、优先级、负责人筛选
- 异常订单自动生成工单的简单场景

你还应该写一份工单状态流转说明。

## 复盘问题

- 工单解决了什么业务问题？
- 工单状态为什么不能随便跳？
- 自动创建工单会不会制造太多噪音？
- 面试官问“这个功能有什么实际价值”时，我怎么回答？
