# 01 项目理解与业务建模

## 今天要建立的理解

你要先搞清楚 OpsFlow 不是一个普通“管理系统”，而是一个模拟企业内部运营的业务平台。它的核心不是页面多，而是让订单、库存、异常处理和操作追踪形成一个完整闭环。

你需要能回答：这个系统给谁用？解决什么问题？为什么公司愿意让初级开发者参与这种系统？它和澳洲市场里的制造业内部系统、支付平台、POS 系统、SaaS 后台有什么关系？

## 你要重点考虑的问题

先把用户角色想清楚。Admin、Operator、Viewer 不是为了凑权限，而是代表真实公司的不同职责。Admin 负责配置和管理，Operator 负责处理业务，Viewer 负责查看数据。你要想：如果没有这些角色，系统会出现什么风险？

再把业务流程想清楚。一笔订单从创建到完成，中间会发生库存校验、库存扣减、订单状态变化、日志记录、异常处理。你要关心的是这些动作的先后顺序，以及失败时系统应该怎么办。

还要思考项目边界。你不是要做完整电商平台，不需要购物车、推荐系统、营销活动、复杂支付网关。你要做的是企业后台系统里最能体现 Java 后端能力的部分：业务状态、数据一致性、异常排查和可维护性。

## 建议你查什么

查“订单管理系统业务流程”、“库存管理系统设计”、“后台运营系统权限设计”、“工单系统是什么”。不要只看代码教程，也要看产品介绍和真实业务系统截图。你要训练自己从业务角度理解技术。

可以重点查这些关键词：

- order management system workflow
- inventory management system database design
- admin dashboard order operations
- ticket management system workflow
- audit log business system

## 怎么问 AI 更有效

不要问：“帮我做一个订单系统。”

更好的问法是：

“我准备做一个 Java Spring Boot 项目，场景是企业内部订单库存和工单管理。目标岗位是澳洲初级 Java/业务系统开发。请帮我判断这个项目的业务边界应该怎么定，哪些功能适合做，哪些功能会分散重点。”

也可以问：

“我现在把用户分成 Admin、Operator、Viewer。请你从真实企业后台系统角度，帮我检查这三个角色的职责是否合理，还缺不缺角色。”

## 你应该产出的东西

你需要写出一段项目介绍，能放进 README：

OpsFlow 是一个面向企业内部运营人员的订单库存与异常工单管理系统，支持商品库存管理、订单创建、库存扣减、异常工单处理、操作日志审计和后台数据查询。项目重点模拟真实业务系统中的订单状态流转、库存一致性、防重复提交和异常排查场景。

你还要画出一份文字流程图，哪怕很粗糙也可以。重点是让你知道每个模块为什么存在。

## 复盘问题

- 我能不能用 1 分钟讲清楚这个项目？
- 这个项目和招聘市场里的 Java 岗位有什么关系？
- 哪些功能是核心，哪些只是装饰？
- 如果面试官问“为什么做这个项目”，我能不能说出业务原因？
