# 07 Redis 防重复与限流

## 今天要建立的理解

Redis 不是为了让项目显得高级，而是用来解决内存级快速读写和临时状态的问题。在这个项目里，Redis 最适合用来做防重复提交、限流、短期 token、热点数据缓存。

## 你要重点考虑的问题

先理解幂等性。用户点击一次创建订单和点击两次创建订单，系统不应该产生两笔重复订单。你要知道重复提交可能来自前端重复点击、网络重试、用户刷新、接口被重复调用。

再理解 Redis token 方案。前端先请求一个下单 token，创建订单时带上 token。后端检查 token 是否存在，存在则删除并继续，不存在则拒绝。这里重点是“检查和删除”要尽量保证原子性。

限流也要结合业务理解。不是所有接口都需要限流，但创建订单、登录、获取下单 token 这类接口可以做简单限制。你要思考限流失败时给用户什么提示。

## 建议你查什么

推荐关键词：

- idempotency key order API
- Redis setnx idempotency
- Redis Lua check and delete token
- rate limiting Redis fixed window
- Spring Boot RedisTemplate best practice

查资料时要分清：缓存、幂等、锁、限流是不同问题，不要把所有 Redis 用法混成一个概念。

## 你应该产出的东西

你需要实现：

- 获取下单 token 接口
- 创建订单时校验 token
- token 用过后失效
- 重复提交返回明确错误
- 简单用户级限流

最好在 README 里写一个 Redis 使用说明，说明每类 key 的含义和过期时间。
