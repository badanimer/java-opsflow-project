# 04 商品与库存模块

## 今天要建立的理解

商品和库存是订单系统的基础。商品描述“卖什么”，库存描述“还能卖多少”。这两个概念不能混在一起，否则后面做订单、扣库存、库存不足、库存调整都会变乱。

## 你要重点考虑的问题

商品模块要考虑生命周期。商品不是只有新增、查询、修改、删除。真实系统里商品可能上架、下架、停用。你要想：已经产生订单的商品还能不能删除？如果不能，应该怎么处理？

库存模块要考虑安全性。库存增加可能来自入库，库存减少可能来自下单、损耗、人工调整。即使你项目里不做完整入库系统，也要知道库存变动最好可追踪。

你还要考虑参数校验。价格不能小于 0，库存不能小于 0，商品名不能为空，下架商品不能下单。这些规则都是业务逻辑，不只是代码细节。

## 建议你查什么

推荐关键词：

- product inventory management system design
- stock adjustment audit trail
- Spring Boot validation annotation
- inventory deduction transaction
- soft delete product after orders

查的时候注意：很多教程只会教 CRUD，你要额外关注状态、校验和错误处理。

## 怎么问 AI 更有效

你可以问：

“我正在做商品和库存模块。商品表和库存表分开了。请你帮我列出这个模块应该有哪些业务规则，哪些规则必须写在后端，哪些可以只在前端提示。”

或者：

“如果商品已经产生订单，删除商品会有什么问题？请用企业后台系统的角度解释，并给我适合毕业生项目的处理方案。”

## 你应该产出的东西

你需要完成商品和库存接口，并能通过 Swagger 测试：

- 新增商品
- 修改商品
- 查询商品列表
- 查询商品详情
- 上架和下架商品
- 查询库存
- 增加库存
- 扣减库存

同时，你应该整理一份业务规则说明，写进 README 或 docs。

- 下架商品还能不能被查询？
- 库存不足时，系统应该返回什么错误？
