# 12 测试、接口文档与数据校验

## 今天要建立的理解

测试和文档决定项目像不像真实工程。一个能跑的项目不等于可靠项目。你需要证明核心流程被验证过，接口别人能看懂，错误输入不会把系统弄乱。

## 你要重点考虑的问题

先考虑测什么。不要为了覆盖率写无意义测试。核心测试应该围绕业务风险：库存不足、重复提交、订单创建成功、订单失败回滚、工单状态更新、权限不足。

再考虑接口文档。Swagger 不只是自动生成页面，你要让接口名称、参数、返回结果和错误情况尽量清楚。面试官打开后应该能知道怎么测试。

还要考虑参数校验。后端必须自己校验，不要相信前端。空值、负数、不存在的 ID、非法状态流转、无权限访问，都应该有明确返回。

## 建议你查什么

推荐关键词：

- Spring Boot unit test service Mockito
- Spring Boot integration test controller
- Swagger OpenAPI Spring Boot annotations
- Bean Validation Spring Boot
- test cases order inventory system

重点学习 service 测试怎么测业务逻辑，controller 测试怎么测接口行为。

## 怎么问 AI 更有效

可以问：

“这是我的订单创建 service。请你帮我设计高价值测试用例，不要追求数量，重点覆盖库存一致性、异常和重复提交。”

也可以问：

“请你根据我的接口列表，帮我检查 Swagger 文档是否足够让别人独立测试这个项目。”

## 你应该产出的东西

你需要完成：

- 核心 service 测试
- 参数校验
- 全局异常返回
- Swagger 文档
- Postman 或 Apifox 测试集合
- README 中的接口测试说明

## 复盘问题

- 我测的是业务风险还是普通 getter/setter？
- 哪些错误输入最可能发生？
- 我的接口文档能不能让别人不用问我也会测？
- 如果面试官问“你怎么保证这个功能没问题”，我怎么回答？
