# 11 RabbitMQ 异步任务

## 今天要建立的理解

RabbitMQ 的价值是把不需要立刻完成的事情从主流程里拆出去。订单创建接口最重要的是快速、可靠地创建订单和扣库存。通知、日志补充、库存同步、超时取消等后续任务可以异步处理。

## 你要重点考虑的问题

先区分同步和异步。同步适合必须马上知道结果的事情，比如库存是否足够。异步适合可以稍后处理的事情，比如发送通知、生成运营提醒、处理失败补偿。

再考虑失败。消息发送失败怎么办？消费者处理失败怎么办？重复消费怎么办？你不需要实现工业级 MQ 系统，但要知道这些问题存在。

还要考虑项目复杂度。不要为了用 RabbitMQ 把所有东西都异步化。订单创建和库存扣减仍然应该保持清晰可靠。MQ 是辅助，不是替代事务。

## 建议你查什么

推荐关键词：

- RabbitMQ order system async processing
- message queue retry dead letter queue
- Spring Boot RabbitMQ producer consumer
- order timeout cancel message queue
- idempotent message consumer

查资料时重点看使用场景和失败处理，不要只看 producer/consumer 示例代码。

## 怎么问 AI 更有效

可以问：

“在我的订单库存系统里，哪些动作应该同步处理，哪些动作适合放到 RabbitMQ 异步处理？请你按业务重要性帮我区分。”

也可以问：

“消费者重复消费同一条订单消息会有什么问题？请用初级项目能实现的方式讲讲如何避免重复处理。”

## 你应该产出的东西

你需要完成：

- 订单创建后发送消息
- 消费者处理订单后续任务
- 简单失败重试或失败记录
- 失败时创建工单或写日志
- README 解释为什么使用 MQ

如果时间紧，MQ 做一个清晰场景就够，不要贪多。
